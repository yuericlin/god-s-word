# God's Word — User Requirements

Captured from the user's directives across the full development conversation
(Oct 17–19, 2026). These are the source of truth for behavior; each requirement
has corresponding tests in `SwordReaderTests` (where the logic is testable
outside SwiftUI).

## Standing principles

- **Implement without changing rendering.** Never alter the native paragraph text
  rendering to add a feature; layer interactions on top (e.g., invisible links).
- **The simpler the better.** Prefer the minimal implementation that satisfies the
  requirement.
- **The user drives all sends and tags.** Releases are tag-gated: the user pushes
  the `v1.0` tag themselves. `project.pbxproj` is generated by
  `tools/gen_pbxproj.py` — never commit Xcode's version; re-run the generator.

---

## 0. App overview

- Minimalistic, performant iPhone Bible reader (iOS 17+, bundle
  `com.lys.godsword`).
- Downloads any Bible version from the CrossWire SWORD repository; renders one
  chapter at a time; **no bundled text**.
- Pure-Swift clean-room SWORD zText reader (SwordReader package, zero
  dependencies).
- Personal data stored locally (UserDefaults + Application Support) by default.
  Opt-in Google Drive backup (private `appDataFolder`, manual OAuth PKCE, no
  SDK) only with consent + Google sign-in.
- Distribution: unsigned `.ipa` via GitHub Actions; user installs via Xcode from
  source (⌘R) on their own iPhone. App Store later (deferred).

### SWORD format (verified facts)
- CrossWire root `https://crosswire.org/ftpmirror/pub/sword/raw`; catalog
  `mods.d.tar.gz` (~428 confs); module zip = `{root}/packages/<ModuleID>.zip`
  (case-sensitive).
- zText per testament: `.bzv` 10-byte LE verse index (block u32, start u32, size
  u16), `.bzs` 12-byte block index, `.bzz` zlib blocks each followed by 1024
  bytes zero padding.
- KJV = **31,102 verses**. ChiUns = **31,032 real verses** (~71 index entries
  are 并入上节 / merged into previous verse).
- KJV and ChiUns contain **zero `<p>` markers**; no section subtitles in the data
  (only psalm/acrostic `<title>` types).

## 1. Verse picker

### Selection
- **REQ-VP-1:** Tapping a verse selects it. The selected verse shows a light sky
  blue highlight (`UIColor(0.53, 0.81, 0.98, alpha 0.55)` via `backgroundColor`).
- **REQ-VP-2:** Tapping a selected verse again unselects it.
- **REQ-VP-3:** Multiple verses can be selected at once.
- **REQ-VP-4:** Selection is cleared when the testament, book, or chapter changes.
- **REQ-VP-5:** Selection is KEPT when the Bible version changes (same chapter,
  different version).

### Implementation constraint
- Verses are tappable via invisible `verse://N` links on the native
  `AttributedString`. Link styling is neutralized (`underlineStyle = []`,
  `foregroundColor = .primary` unless the run already has a color) so rendering
  is pixel-identical to the original paragraph.

## 2. Copy

### Format
- **REQ-CP-1:** The clipboard text puts the verse(s) between two double quotes.
- **REQ-CP-2:** After the closing quote: book name, chapter, verses, then the
  Bible version. Format: `"text" Book Chapter:Verses Version`.
- **REQ-CP-3:** If only one verse is selected, the verse number is NOT included
  in the quoted text.
- **REQ-CP-4:** If multiple verses are selected, each verse's number IS included
  before its text inside the quotes (`"1 text 2 text"`).
- **REQ-CP-5:** Verse ranges in the reference are compressed: `[1,2,3,5]` →
  `"1-3, 5"`.

### Examples
Single (KJV Gen 1:1):
```
"In the beginning God created the heaven and the earth." Genesis 1:1 KJV
```
Multiple (KJV Gen 1:1-2):
```
"1 In the beginning God created the heaven and the earth. 2 And the earth was without form, and void; and darkness was upon the face of the deep." Genesis 1:1-2 KJV
```

## 3. Notes

### Anchoring
- **REQ-NT-1:** A note is scoped to either the entire chapter OR the selected
  verses.
- **REQ-NT-2:** When created from selected verses, the note anchors to the
  FIRST selected verse (lowest number). The note indicator appears only there.
- **REQ-NT-3:** ~~A chapter note is anchored at verse 1.~~ Superseded by
  REQ-NT-15: chapter notes are their own scope, stored separately.
- **REQ-NT-4:** Long-press on empty reading area offers "Take Notes", which
  creates a chapter-level note (REQ-NT-15).

### Indicator
- **REQ-NT-5:** A verse with a note shows a yellow background highlight on its
  verse number (`UIColor(1.0, 0.9, 0.45, alpha 0.55)`).
- **REQ-NT-6:** Tapping the highlighted verse number opens the note editor.
  (The highlight uses `backgroundColor`, which — unlike `foregroundColor` — is
  not overridden by link styling.)

### Editor
- **REQ-NT-7:** The note editor auto-focuses on appear: cursor shows and the
  keyboard comes up (via `@FocusState` with a 0.4s delay after the sheet
  animation).
- **REQ-NT-8:** The editor is self-contained: it loads the note text from
  `PersonalData` using the note key on appear, and saves via `PersonalData` on
  Save. Callers pass only the key and reference string.

### Storage
- **REQ-NT-9:** Notes persist in `UserDefaults` (`gw.verseNotes.v1`).
- **REQ-NT-10:** Notes are included in Drive backup payloads (v5). Applying an
  old backup never wipes existing notes.
- **REQ-NT-11:** Note storage key format: `"{testament}:{book}:{chapter}:{verse}"`
  (version-less since REQ-NT-19; older builds prefixed the module id).
- **REQ-NT-12:** A new note opens pre-filled (seeded): with verses selected,
  the selection in exactly the clipboard format (`"verse text" Book
  Chapter:Verses Version`; single verse unnumbered inside the quotes,
  multiple verses numbered), followed by a newline; with no selection,
  "Book Title Chapter" plus a newline. The seed never replaces an existing
  note's text; Save compares against the saved text, so a seeded new note
  can be saved as-is and shows no Delete button.
- **REQ-NT-13:** Note save order is tracked (`gw.verseNoteOrder.v1`, most
  recent first; saving a note moves its key to the front, deleting removes
  it). The order is included in Drive backups and manual exports
  (`noteOrder.json`) and restored by both.

### Scoped notes (book / chapter / verse levels)
- **REQ-NT-14:** Notes exist at three scopes, mirroring commentary's
  levels: a **book note** (one per book), a **chapter note**
  (one per chapter), and **verse notes** (REQ-NT-9..13, unchanged). Book
  and chapter notes live in their own stores — `PersonalData.bookNotes`
  (`gw.bookNotes.v1`, key `"{testament}:{book}"`, see
  `BookNoteKey`) and `PersonalData.chapterNotes` (`gw.chapterNotes.v1`,
  key `"{testament}:{book}:{chapter}"`, see
  `ChapterNoteKey`). An empty save deletes the note. They are included in
  Drive backups (payload v7), iCloud sync (`bookNotes.json` /
  `chapterNotes.json`), and manual export/import; applying older backups
  or files never wipes them.
- **REQ-NT-15:** Chapter notes supersede the verse-1 anchoring of the old
  REQ-NT-3: "Take Notes" (reader long-press) and the bookmarks panel's
  "Add Note" with no verse selected both edit the chapter-level note.
  With verses selected, "Add Note" still edits the verse note anchored at
  the first selected verse (REQ-NT-2). Verse notes written at verse 1
  before this change remain verse notes.
- **REQ-NT-16:** Because a pre-REQ-NT-15 chapter note is indistinguishable
  from a genuine verse-1 note, nothing migrates automatically. When a
  chapter has no chapter-level note but does have a verse-1 note, the
  panel's Chapter scope shows that note labeled as stored on verse 1 and
  offers "Move to Chapter Note", which copies it into the chapter store
  and removes the verse-1 note (an explicit user action only).
- **REQ-NT-17:** Every note (verse, chapter, and book) records when it
  was created and when it was last edited, in a per-scope times store
  keyed like the notes themselves (`NoteTimes`). A first save stamps
  both times; saving changed text moves only the last-edit time;
  saving identical text stamps nothing; deleting a note deletes its
  times. Notes written before this have no creation time — their
  first later edit stamps the last-edit time only. The Notes tab
  appends the last-edit date to the note's title line —
  "Proverbs 8:31 - Oct 22, 2026" — date only, no "Updated"
  label, and nothing under the note. The times
  travel with the notes: UserDefaults, payload v8, iCloud files, and
  manual export/import.
- **REQ-NT-18:** The Notes tab has four sub-tabs, in this order:
  **Recents** — every note, from any version (REQ-NT-19), from any
  book, most recently updated first (REQ-NT-17 times; notes without
  times fall back to the verse-note order); **Book** — every note
  in the active book (the book note, then chapter and verse notes
  in reading order); **Chapter** — every note in the active
  chapter (the chapter note, then verse notes by verse; the legacy
  verse-1 presentation of REQ-NT-16 still applies and is not
  repeated as a verse row); **Verse** — the note on the selected
  verse (the first selected verse for multi-verse selections). No
  sub-tab is scoped to the version being read. A sub-tab is shown
  only when it
  has notes; when the selected sub-tab becomes empty (e.g. after
  navigating), the nearest visible sub-tab takes its place (ties
  go to the earlier sub-tab; this logic is `NotesTabLogic` in
  SwordReader, unit-tested). When there are no notes at all, the
  sub-tab bar hides and one empty state shows. An add-note entry
  point (for the selected verse) is always available, even when
  the Verse sub-tab is hidden; the Book and Chapter sub-tabs offer
  their own add entry when their scoped note is missing. Tapping a
  note row opens its editor in place. (Supersedes the Notes half
  of REQ-AP-9.)
- **REQ-NT-19:** Notes belong to their book/chapter/verse, not to a
  version: a note written while reading one version is visible —
  and editable — in every version (the verse highlight, all Notes
  sub-tabs, and the editors use the version-less keys of
  REQ-NT-11/14). Each note remembers the version it was first
  written in (`PersonalData.noteSources`, `gw.noteSources.v1`); the
  Notes list shows it as a tag on the note's title line —
  "Isaiah 53:4 · NASB - Oct 22, 2026" (before the REQ-NT-17 date).
  Sources travel with the notes: payload v10 (REQ-BK-6), iCloud
  (`noteSources.json`), and manual export/import; a "Move to
  Chapter Note" (REQ-NT-16) carries the note's source with it.
  Notes stored by older builds under per-version keys migrate on
  launch, and again whenever a backup, iCloud load, or import
  applies data: keys lose their module prefix, and notes that
  collide on the same book/chapter/verse merge into one — distinct
  texts joined newest-first with a blank line between (an already
  version-less entry counts as newest; then the verse-note order,
  then last-edit time; ties break by key), times keep the earliest
  creation and the latest edit, and the source is the newest
  merged note's version. The migration is idempotent: with no
  per-version keys present it changes nothing.

## 5. Strong's numbers

- **REQ-ST-1:** The "Strong's numbers" toggle appears in Settings only when the
  current version supports Strong's (conf lists `GlobalOptionFilter=OSISStrongs`).
  KJV and ChiUns both support it.
- **REQ-ST-2:** Strong's numbers default to hidden.
- **REQ-ST-3:** When enabled, tappable Strong's numbers appear after words in
  both paragraph and verse-by-verse modes.
- **REQ-ST-4:** Tapping a number downloads the Strong's Hebrew/Greek lexicon
  from CrossWire on first use, then shows the dictionary entry.
- **REQ-ST-5:** ChiUns-specific numbers H9001–H9004 (Hebrew inseparable
  prepositions: לְ "to/for", בְּ "in/with", כְּ "as/like") show built-in
  bilingual definitions; they have no standard Strong's entry.
- **REQ-ST-6:** Morphology codes hiding in lemmas (Hebrew > 8674, Greek > 5624)
  are filtered out and never displayed.
- **REQ-ST-7:** Cross-references inside a dictionary entry are
  tappable links (`StrongsReferences` in SwordReader,
  unit-tested). A reference displays as its canonical key —
  the lexicon letter plus the number zero-padded to four
  digits ("HEBREW 0166" → "H0166", "GREEK 427" → "G0427") —
  whether the source writes it as a see-reference ("see
  HEBREW for 02986") or as a bare same-lexicon number in the
  body ("from 2986"); Greek entries can cite Hebrew entries
  and vice versa. Tapping opens the referenced entry in
  place. Scripture citations ("(2 Sam. 23:20)", "25:25"),
  word-glued digits ("H8674"), and the entry's own header
  number are not links.
- **REQ-ST-8:** The dictionary view keeps a history of the
  entries viewed in the session, with back/forward arrows in
  a bottom bar: back returns to the previously viewed entry,
  and forward — enabled only after going back — reopens the
  entry backed away from; tapping a new reference clears the
  forward side, like a browser.

## 6. Gestures (final map, Oct 19)

- Right edge swipe left = forward (versions → books → chapters → reader; at
  reader opens bookmarks panel).
- Right edge swipe right = backward.
- Left edge = settings drawer (reader only).
- Middle swipes turn chapters (crossing books at the edges, REQ-GS-1).

- **REQ-GS-1:** Middle swipes turn chapters across book
  boundaries: swiping forward (right to left) in a book's last
  chapter opens the next book's first chapter, and swiping
  backward (left to right) in a book's first chapter opens the
  previous book's last chapter (`BookLocation.adjacentBook`,
  unit-tested). The Bible wraps — forward from Revelation 22
  opens Genesis 1, and backward from Genesis 1 opens Revelation
  22. The bottom-bar chapter arrows do the same (they call the
  same turn, so they cross and wrap identically, and are never
  disabled: with the wrap, every chapter has a previous and a
  next).

## 7. Reading history

- **REQ-HI-1:** Every visited chapter is logged to `PersonalData.historyLog`
  (`gw.historyLog.v1`).
- **REQ-HI-2:** The log is capped at 100 entries; oldest entries are dropped.
- **REQ-HI-3:** Revisiting a chapter moves its entry to the front (no
  duplicates within the combine window, REQ-HI-7).
- **REQ-HI-4:** The app restores the last reading position on launch.
- **REQ-HI-5:** The Settings screen has a History section with jump-to-entry.
- **REQ-HI-6:** Bookmark jumps do NOT record history immediately. A 60-second
  dwell timer starts on arrival; the chapter is recorded only if the user is
  still there when it fires. Turning chapters restarts the timer. Normal
  immediate recording resumes after a dwell completes.
- **REQ-HI-7:** Visits to the same chapter combine into one entry when they
  fall within 24 hours of the entry's earliest visit. The entry keeps every
  timestamp and every version read (most recent version last; `moduleID` is
  that one). A visit 24 hours or more after the earliest starts a new entry.
  A reload within 60 seconds adds no timestamp. History saved before this
  rule (one version and timestamp per entry) still loads, and is combined
  when loaded or imported.
- **REQ-HI-8:** Each history row shows the chapter, all its versions, and the
  entry's earliest timestamp as a date and time (with the year only when not
  the current year), not a time-ago.
- **REQ-HI-9:** The history list shows the latest 20 entries, followed by a
  "…" row when there are more. The log itself still keeps up to 100 (REQ-HI-2).

## 8. Bookmarks (ribbons)

- **REQ-BM-1:** Fresh installs start with **zero** bookmarks.
- **REQ-BM-2:** New bookmarks take colors from `defaultPalette` in order, cycling
  after five: 1 light sky blue (0.53,0.81,0.98), 2 light gold (1.00,0.84,0.40),
  3 light purple (0.79,0.66,0.91), 4 light silver (0.83,0.83,0.83), 5 light
  green (0.56,0.93,0.56).
- **REQ-BM-3:** While reading, small vertical ribbons show at the top-right
  corner, but ONLY for bookmarks pointing at the chapter being read. Unmarked
  chapters show nothing.
- **REQ-BM-4:** The bookmarks panel shows small translucent ribbons at its
  top-right corner, one per bookmark.
- **REQ-BM-5:** Single tap on a bookmark jumps to its chapter.
- **REQ-BM-6:** Holding a bookmark for 1 second offers: Assign (point it at the
  chapter being read), Edit (name, ribbon color, book & chapter), Delete.
- **REQ-BM-7:** Bookmarks persist in UserDefaults (`gw.bookmarks.v1`) and Drive
  backups (payload v4+). Old backups load without wiping bookmarks.

---

- **REQ-BM-8:** The reader's long-press menu (on the margins and gaps around
  the text) has **Assign Bookmark** next to Take Notes. It opens a sheet with
  a **New Bookmark** row and the existing bookmarks. New Bookmark opens the
  editor on a new bookmark at the chapter being read (REQ-BM-9). Choosing an
  existing bookmark moves it to the chapter being read (the same as Assign,
  REQ-BM-6).
- **REQ-BM-9:** A new bookmark (Add Bookmark in the panel, New Bookmark in
  Assign) is a draft until the user taps Save in its editor, which titles it
  "New Bookmark". Cancel, or swiping the sheet down, discards it: nothing is
  stored. Editing an existing bookmark is unchanged; Cancel keeps it as it was.
- **REQ-BM-10:** Every bookmark records when it was created and when it
  was last changed (`createdAt` / `updatedAt` on the bookmark itself).
  Saving a new bookmark stamps both; saving an edit or assigning the
  bookmark to another chapter stamps only the last-change time. The
  times are kept in the data (and backups); the bookmarks panel's
  labeled ribbons show the name and one line with the book and chapter
  followed by the last-change date, with no "Updated" label \u2014
  "Genesis 12 - Oct 22, 2026" (book and chapter, then " - ", then
  the date). Bookmarks written before this carry no
  timestamps and show just the book and chapter until they are next
  saved or assigned.
- **REQ-BM-11:** Bookmarks are version-independent: a bookmark names
  a testament/book/chapter only (no version is stored with it), so
  a bookmark set while reading one version shows — reader ribbons,
  panel, and jumps — in every version. Same sharing rule as notes
  (REQ-NT-19); bookmarks never carried a version.

## 9. Two-level book/chapter picker

- **REQ-PK-1:** The reader's top book menu opens a two-level picker sheet (not
  just landing on chapter 1).
- **REQ-PK-2:** The books list (OT/NT sections) drills into a chapter grid; the
  user picks the exact chapter.
- **REQ-PK-3:** The current book shows a checkmark; the current chapter is
  highlighted.
- **REQ-PK-4:** The reader's top title shows the book name with the chapter

- **REQ-PK-5:** Picking a Bible version in the library keeps the book and
  chapter being read; the chapter is clamped to the new version's range. The
  first pick, or a version that lacks the current book, starts at Genesis 1.

## 10. Reading settings

- **REQ-RS-1:** 'Verse by verse' toggle in Settings > Reading (default OFF).
  Persisted in UserDefaults and Drive backup.
- **REQ-RS-2:** The settings drawer is opened by left-edge swipe (reader only).
  No gear button (removed at user's word: "I don't like the button").
- **REQ-RS-3:** The drawer close drag is scoped to the handle only, so it never
  swallows toggle drags.
- **REQ-RS-4:** The Strong's numbers toggle appears only when the version
  supports Strong's (see REQ-ST-1).
- **REQ-RS-5:** A section heading ("subtitle") a version prints before
  a verse — an OSIS preverse section title, e.g. NASB's "The Seventy
  Sent Out" at Luke 10:1 — renders as a semibold heading in the
  reading serif: its own line above the verse in paragraph mode,
  its own row in verse-by-verse mode, in both plain and Strong's
  renderings. The heading no longer appears inline in the verse
  text. Canonical psalm titles are scripture text and stay in the
  verse. Versions whose modules carry no such titles are
  unaffected. Private JSON versions carry a heading as a "¶…¶"
  prefix on the verse string (the NKJV+ convention) and are
  treated exactly the same way; the pilcrow markers never render.

## 12. Backup (Drive)

- **REQ-BK-1:** Payload v7 includes: reading settings, history log, bookmarks,
  verse notes, Strong's visibility, Compare versions (REQ-CM-7), book and
  chapter notes, the commentary module and Strong's fallback settings
  (REQ-NT-14, REQ-AP-6/7). Payload v6 and older still load; fields they
  lack never wipe existing data.
- **REQ-BK-2:** Applying an old backup never wipes newer data types (notes,
  bookmarks, ribbons).
- **REQ-BK-3:** Backup is opt-in, manual, to the private `appDataFolder`.
- **REQ-BK-4:** Payload v8 adds bookmark timestamps and the note-times
  stores (REQ-BM-10, REQ-NT-17). Payload v7 and older still load;
  missing timestamps decode as absent and never wipe existing ones,
  and times for notes that don't exist are dropped on apply. Older
  app versions ignore the new fields.
- **REQ-BK-5:** The Google Drive backup and iCloud sections are
  hidden in Settings for now; of the backup/sync sections only
  Manual backup (export/import) shows. The features and their
  code stay in place (payload, sync, and restore paths
  unchanged); only the settings UI is not shown. Re-enable by
  flipping the sections' visibility flags in Settings.
- **REQ-BK-6:** Payload v10 adds the note-sources store
  (REQ-NT-19). Payload v9 and older still load; a payload without
  sources leaves existing sources alone, and the REQ-NT-19
  migration derives sources from the payload's legacy per-version
  keys when it carries them.

## 13. iCloud sync

- **REQ-IC-1:** iCloud sync is offered BEFORE Google Drive (preferred method).
  Toggle in Settings > iCloud. Requires iCloud account sign-in.
- **REQ-IC-2:** When enabled, all data syncs to the `god-s-word/` folder in
  iCloud Drive.
- **REQ-IC-3:** Data is stored in **JSON format** (not binary):
  - `bookmarks.json` — ribbon bookmarks
  - `notes.json` — verse notes (`{key: text}`)
  - `settings.json` — font size, toggles, repository URL, installed module IDs
  - `history.json` — reading history log
- **REQ-IC-4:** Both plain JSON (`.json`) and compressed JSON (`.json.gz`) are
  supported. Save defaults to plain; load tries `.gz` first, then `.json`.
- **REQ-IC-5:** A `god-s-word/private-repo/` subfolder stores private or
  customized Bible versions (JSON or gzipped JSON modules).
- **REQ-IC-6:** On launch with iCloud enabled, data loads from iCloud Drive
  (non-empty values only; never wipes local data with empty cloud data).
- **REQ-IC-7:** Changes sync to iCloud automatically (write-through on every
  `didSet`).
- **REQ-IC-8:** Requires the iCloud Drive capability (`GodsWord.entitlements`;
  enable in Xcode Signing & Capabilities with the user's Apple Developer
  account).

### Private Bible versions
- **REQ-IC-9:** Private/custom Bible versions are stored as JSON (or gzipped
  JSON) in `god-s-word/private-repo/`.
- **REQ-IC-10:** When iCloud is enabled, private Bibles are automatically
  downloaded to local `Application Support/PrivateModules/`. Downloads ONLY
  occur when the iCloud toggle is enabled — never when disabled.
- **REQ-IC-11:** Private Bible JSON schema:
  ```json
  {
    "id": "MyVersion",
    "name": "My Custom Bible",
    "language": "en",
    "books": [
      { "name": "Genesis",
        "chapters": [ ["v1 text", "v2 text"], ["ch2 v1"] ] }
    ]
  }
  ```
  Chapters are arrays of verses (0-based in JSON, 1-based in the API).
- **REQ-IC-12:** Both `.json` and `.json.gz` are supported for private modules.

## 14. Compare

### Action
- **REQ-CM-1:** The selection bar (shown while verses are selected) has a
  **Compare** action next to Copy and Notes.
- **REQ-CM-2:** Compare opens a panel titled with the reference
  (`Book Chapter:Verses`, ranges compressed as in REQ-CP-5) showing the
  selected verses in each version, one section per version (short label plus
  full name). Verse numbers show only when several verses are selected
  (as in REQ-CP-3/4); a verse a version lacks shows a dash. The selection
  is kept when the panel closes.

### Which versions
- **REQ-CM-3:** If the Compare versions setting is empty (or never set), the
  panel shows only the current version.
- **REQ-CM-4:** Otherwise it shows the chosen versions union the current
  version: the current version first, then the chosen ones in library order
  (the order of the version picker, not the order they were ticked). The
  current version is never shown twice.
- **REQ-CM-5:** A chosen version that is no longer installed is skipped.

### Setting
- **REQ-CM-6:** The setting is a multi-select list of every installed version
  (downloaded and private). It is reachable from Settings > Compare and from
  the Compare panel's Versions button, and changing it updates the open
  panel.
- **REQ-CM-7:** The setting persists in `UserDefaults`
  (`gw.compareVersions.v1`), in Drive backups (payload v6) and in
  `settings.json` for iCloud sync and manual export. Older backups and
  settings files (no Compare field) load without wiping the setting.

## 15. Auxiliary panel

- **REQ-AP-1:** Below the main reading panel sits an auxiliary panel
  (a real panel under the chapter text, not an overlay; the main text
  rendering is untouched). It has four tabs — **Notes**, **Commentary**,
  **Strong's**, **Recents**. The panel starts collapsed; collapsed, it
  renders nothing at all — the only trace is a toggle button in the
  reader's bottom bar, next to the chapter controls: an up arrow when
  collapsed (tap to expand), a down arrow when open (tap to collapse).
- **REQ-AP-2:** The Notes tab has **Book / Chapter / Verse** sub-tabs.
  Each shows the scoped note for the book / chapter / selected verse
  being read (REQ-NT-14) with an Add/Edit action opening the note
  editor. The Verse sub-tab anchors at the lowest selected verse
  (verse 1 when nothing is selected).
- **REQ-AP-3:** The Commentary tab has the same **Book / Chapter /
  Verse** sub-tabs, showing the chosen commentary's content at that
  scope for the passage being read.
- **REQ-AP-4:** A commentary is a SWORD **zCom** module. It is
  renderable when it is OSIS, ZIP-compressed, whole-book blocks, UTF-8,
  KJV/NRSV versification, and not enciphered (`ModuleInfo.isCommentary`
  / `isCommentaryRenderable`; verified against MHCC — zCom shares the
  zText `.bzv/.bzs/.bzz` layout, so `SwordModule` reads it unmodified).
  ThML commentaries (e.g. TSK) are not renderable yet. Commentaries are
  downloadable in the Repository (badged "Commentary") and never appear
  in the Bible version lists (Library, version picker, Compare).
- **REQ-AP-5:** A commentary stores one entry covering a run of verses
  by repeating the same text at each verse it covers. The Chapter scope
  collapses those consecutive duplicates into verse-range entries
  (`CommentaryGrouping`); the Verse scope shows the single entry
  covering the selected verse; the Book scope shows the whole book's
  entries grouped by chapter, chapters collapsed except the one being
  read.
- **REQ-AP-6:** The commentary shown is `PersonalData.commentaryModuleID`
  (persisted, in backups and `settings.json` like the Compare setting).
  Empty/uninstalled means the first installed renderable commentary.
  It is chosen in Settings > Auxiliary panel > Commentary or in the
  panel's own header menu. With no commentary installed, the tab shows
  an empty state offering the Repository.
- **REQ-AP-7:** The Strong's tab renders the selected verse (lowest
  selected verse; verse 1 when none) with tappable Strong's numbers,
  exactly like the main reader's Strong's mode; tapping a number opens
  its dictionary entry. The rendering comes from the version being read
  when it supports Strong's; otherwise from the fallback version in
  `PersonalData.strongsFallbackVersionID` (Settings > Strong's, or the
  panel's own menu); when that is unset or uninstalled, the first
  installed Strong's version. Resolution is `StrongsVerseSource.resolve`.
  Private versions never supply Strong's. With no Strong's version
  installed, the tab explains so.
- **REQ-AP-8:** Commentaries are often copyrighted, so the panel's
  Commentary tab header has an info button opening a sheet with the
  commentary's name, its declared distribution license
  (`ModuleInfo.distributionLicense`, the conf's DistributionLicense
  field), and its About text (which carries the copyright notice).
  The Settings commentary picker also shows the license under each
  commentary's name when one is declared.
- **REQ-AP-9:** The Book / Chapter / Verse sub-tab picker only appears
  when the tab has at least one entry for the current location. For
  Notes, an entry is a book or chapter note (including a legacy
  verse-1 note) or any verse note in the current chapter; with no
  entries the Notes tab falls back to the Verse scope (no picker) so
  the first note can still be added. For Commentary, an entry is an
  entry in the current chapter (or anywhere in the book while the
  Book scope is selected); with none, the tab shows its empty state
  without the picker.
- **REQ-AP-10:** Commentaries are downloaded from a dedicated page
  titled "Add Commentary" (`CommentaryRepositoryView`): the repository
  browser listing only renderable commentaries, each with its declared
  license. It is reached from the panel's Commentary empty state and
  from Settings > Commentary. The "Add Bible" page is unchanged.
- **REQ-AP-11:** The Recents tab is the reading history (REQ-HI-1),
  moved here from the reader's left drawer (the drawer's History
  button is gone; the Settings screen's History section, REQ-HI-5,
  remains). It shows the same HistoryView list: most recent first,
  tap an entry to jump back to it (switching to the entry's version
  when still installed), swipe to delete; a Clear button in the tab
  header clears the log.
- **REQ-AP-12:** Module downloads (both "Add Bible" and
  "Add Commentary") show progress with a cancel button
  (`PackageDownloader`): the row shows the fraction downloaded,
  tapping the cancel button aborts the transfer silently (no error
  alert), and a transfer that stalls (30s without data, 15 minutes
  total) fails with an error instead of spinning forever. The
  downloaded package installs off the main thread, so the page stays
  responsive throughout.
- **REQ-AP-13:** `CommentaryModule.loadChapter` throws when the
  module can't be opened (damaged, missing, unsupported) instead
  of returning an empty chapter. The Commentary tab then shows an
  error state naming the module — never a "no commentary for this
  chapter" message — and a later successful load clears it.
- **REQ-AP-14:** Module .conf files decode tolerantly
  (`SwordConf.decodeText`): UTF-8 when valid, otherwise
  Windows-1252. Older packages from several sources (Bible.org's
  above all) carry cp1252 bytes (®, ©, smart quotes) in their
  confs; strict UTF-8 decoding made those modules fail to
  install with a misleading "no conf found" error and dropped
  them from repository catalogs. The tolerance applies at
  catalog parsing and at install/library scanning alike. ThML
  commentaries are renderable on the same terms as OSIS ones
  (zCom, ZIP, whole-book blocks; a missing Encoding line counts
  as UTF-8 — TSK declares none): their entries pass through the
  same plain-text conversion (verified against TSK). CHAPTER-
  block commentaries remain excluded — their storage is the
  .czv/.czs/.czz layout the reader doesn't handle (e.g.
  NETnotes).
- **REQ-AP-15:** A module covering only one testament (NT-only
  commentaries such as PNT and Lightfoot; some NT-only Bibles)
  opens normally: the missing testament's files (ot.bzv/.bzs/
  .bzz or the nt.* set) read as an empty testament instead of
  failing the whole module load. A partial file set still fails
  as corrupt, and a directory with no testament data at all
  still fails as missing.
- **REQ-AP-16:** Modules using the "4" storage drivers (zText4
  Bibles, zCom4 commentaries) are downloadable and readable on
  the same terms as their classic counterparts. The v4 verse
  index keeps zVerse's heading-slot numbering; only the entry
  format differs (12 bytes per entry with a 32-bit verse size,
  instead of 10 bytes / 16-bit). This unlocks CrossWire modules
  that exist only as zCom4 — TDavid (Spurgeon's Treasury of
  David), MHC (Matthew Henry's Complete Commentary), JFB, and
  KD. Modules in a versification the app doesn't carry
  (Catholic, Vulg) stay excluded regardless of driver.
- **REQ-AP-17:** Modules using the raw storage drivers
  (RawCom commentaries) are downloadable and readable on the
  same terms as compressed commentaries. Raw storage keeps
  zVerse's heading-slot numbering; per testament it is an
  uncompressed data file (ot / nt) plus a .vss index of 6-byte
  records (32-bit offset, 16-bit size), with no CompressType
  or BlockType. GBF is an accepted source type for raw
  commentaries (its tags pass the same plain-text conversion).
  This unlocks DTN (Darby Translation Notes) and The Fourfold
  Gospel on CrossWire. RawText Bibles are not listed yet.
- **REQ-AP-18:** Swiping down inside the auxiliary panel collapses
  it (the same state as the bottom-bar toggle, REQ-AP-1). The
  gesture is simultaneous with the tabs' own scrolling and taps,
  and it fires only on a committed swipe: at least 50 points of
  downward travel with a predicted end of at least 110 points
  (`PanelCollapseGesture` in SwordReader, unit-tested), so
  scrolling a tab's content — including scrolling back up toward
  its top — never collapses the panel by accident.

## 16. Module sources

- **REQ-SRC-1:** The app ships built-in public repository sources:
  the complete SWORD master repository list as far as it is
  reachable over https — CrossWire (the default), CrossWire Beta,
  Bible.org, CrossWire Attic, CrossWire Wycliffe, eBible.org,
  Deutsche Bibelgesellschaft, and the Lockman Foundation (NASB
  1995 / NASB 2020, LBLA, NBLA). (Xiphos is on the master list too
  but is http-only.) Each was verified live in the app's repository
  format (`mods.d.tar.gz` catalog + `packages/<id>.zip`). They
  appear in the source picker on the "Add Bible" and "Add
  Commentary" pages; with more than two repository sources the
  picker is a menu instead of a segmented control. Custom sources
  (repository URLs and local folders) work as before.
- **REQ-SRC-2:** Settings has a Sources section opening a Sources
  page. It lists every source, lets the user pick the default
  download source (persisted; the download pages open with it, and
  changing the source there updates the default), and manages custom
  sources with the same editor as the Library.
- **REQ-SRC-3:** The Sources page has an "Update Public Sources"
  button that downloads `public-sources.json` from the project
  repository and replaces the public preset list by id, showing when
  the list was last updated. The bundled list is the fallback before
  the first update and stays in place if an update fails (the error
  is shown). Custom sources are never touched; modules whose source
  an update removed are listed under CrossWire, and a removed
  default falls back to CrossWire.
- **REQ-SRC-4:** Three .conf quirks must not hide otherwise
  eligible modules: a module that declares no Versification uses
  the SWORD default, KJV (it counts as renderable and the reader
  opens it with the KJV versification); an empty `CipherKey=` line
  means not enciphered; and conf values match case-insensitively,
  as in SWORD (the NET Bible writes `BlockType=Book`). Most
  modules in the Lockman, Bible.org, and Wycliffe repositories
  omit the Versification line, and the NET Bible and NA28 carry
  the empty cipher line, so without this they would never appear
  or open at all.
- **REQ-SRC-5:** The app ships one first-party repository
  source, the Converted Library, served from the `library/`
  folder of the project repository (main branch): public-domain
  works converted from other module formats (e.g. e-Sword) into
  standard SWORD packages. It appears in the source lists like
  the public sources and is part of the downloadable
  public-sources list. Its first module is DarbySynopsis —
  Darby's Synopsis of the Books of the Bible, chapter essays
  for all 1,189 chapters, converted from the public-domain
  text of the Synopsis (1857–62).
- **REQ-SRC-6:** The "Add Bible" download list contains Bibles
  only: modules that are reader-renderable and neither
  commentaries nor dictionaries (`ModuleInfo.isDownloadableBible`).
  Commentaries and dictionaries are downloaded from their own
  lists ("Add Commentary", the dictionary list). Regression
  (Oct 29, 2026): the list once admitted every panel-renderable
  commentary; `isDownloadableBible` and its tests in
  `AuxiliaryPanelRequirementsTests` pin the exclusion, including
  a commentary on a zText driver, which satisfies the renderable
  checks and is caught only by its Category.

## 17. Download languages and dictionaries

- **REQ-LG-1:** Settings > Languages lists the languages the user
  is interested in (primary language codes, e.g. `en`, `zh`). When
  the list is non-empty, every download list — Add Bible, Add
  Commentary, and Add Dictionary — shows only modules in those
  languages; with an empty list nothing is filtered. Matching is
  by primary subtag, case-insensitive (`zh` covers `zh`, `zh-Hans`,
  and `zh-Hant` modules; `ModuleInfo.isInLanguages`), and a module
  with no declared language passes only the empty filter. An
  active filter is announced above the list ("Showing only: …"),
  and a list emptied by the filter says so instead of showing a
  blank page.
- **REQ-LG-2:** The language choices are derived from the catalogs
  of all repository sources: each language shows how many
  downloadable modules (Bibles, commentaries, and dictionaries)
  it has across the sources, de-duplicated by module ID. A
  selected language no catalog currently offers stays listed so
  it can be removed. The selection persists like the other module
  settings: UserDefaults, backup payload v9 (additive; v8 and
  older payloads still load), the iCloud/manual settings file,
  and manual export/import.
- **REQ-LG-3:** Settings has a **Current version** option directly
  under Languages (section "Bible version"), mirroring the
  Commentary option (REQ-AP-6): its row shows the ID of the
  version being read (else the saved last reading's), and its
  page lists the installed versions (`BibleVersion.allInstalled`
  — downloaded modules plus private imports) with the current
  one checkmarked. Picking a version switches the reading to
  it, keeping the place being read with the chapter clamped to
  the new version's range (the reader's own version-picker
  behavior); with no reading open, the pick is saved as the
  last reading so the next book opened uses it. A **Download a
  New Version…** button opens the Add Bible page
  (`RepositoryView`), and the list refreshes when it closes.
- **REQ-LG-4:** The Languages page works like the version
  pickers (REQ-LG-3): it opens on the current selection only
  and fetches nothing — a **Selected** list ("All languages"
  when the selection is empty) where tapping a language
  removes it, plus a **Clear All** button that empties the
  selection back to the all-languages state (REQ-LG-1). The
  full catalog list (REQ-LG-2) is fetched and shown only when
  the user taps **Select Languages…**, which opens it as its
  own sheet with a Done button, like the Add Bible page;
  unselecting therefore never requires scrolling the full
  list on the settings page itself.
- **REQ-DC-1:** Dictionaries (lexicon modules) are a third
  downloadable module type, with an "Add Dictionary" page mirroring
  Add Commentary (source picker, search, license line, progress
  with cancel). A module is a dictionary when it uses an LD driver
  (`zLD`/`RawLD`) and is not a glossary or daily devotional (those
  share the LD drivers); it is downloadable when it is zLD with
  ZIP compression or uncompressed RawLD, is not enciphered, and
  its text is UTF-8 (an absent Encoding is the SWORD default —
  StrongsHebrew declares none). On CrossWire that is 50 of 52
  dictionaries, including Easton, ISBE, Nave, Webster's, and the
  Strong's lexicons in many languages. Installed dictionaries
  never appear in the library's version lists.
- **REQ-DC-2:** Settings > Dictionary chooses the dictionary
  Strong's definitions come from, separately for Hebrew ("H")
  and Greek ("G") keys, from the installed dictionaries. The
  default (no choice) is unchanged: StrongsHebrew / StrongsGreek,
  auto-downloaded on first use into their own store; chosen
  dictionaries are read from the main module store (a chosen one
  that isn't installed falls back to the automatic pair). Only
  Strong's-keyed lexicons have entries for Strong's numbers —
  the Strongs family in any language, BDBGlosses_Strongs,
  AbbottSmithStrongs, MLStrong; other dictionaries install but
  have no Strong's entries to show. The choices persist like
  REQ-LG-2's selection (payload v9).
